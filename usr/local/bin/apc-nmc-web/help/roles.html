Every account belongs to one of four roles (account groups): Administrator, Device, Network and Read-Only. What each role may do is set on Users › User Access › Access Permissions — a checkbox matrix of roles against capabilities.

The Access Permissions matrix

CapabilityUnlocksDefault
UPS SettingsUPS configuration form, outlet-group settings, "Battery Replaced"Device
UPS Control & TestsControl commands, self-test, calibration, schedulesDevice
NotificationsAlert channel configuration and test buttonsNetwork
Network ServicesModbus/FTP/MQTT, firewall, 802.1X, WiFi setupNetwork
Accounts & RADIUSAdd/remove users, RADIUS settings, this matrixAdmin only
System & UpdatesSessions, backup/restore, software updates, support bundle, log clear, boot radio togglesAdmin only
  • Administrator always has every capability — its row is locked so it can't be weakened by accident.
  • Every signed-in user can view all pages and change their own password regardless of the matrix; the matrix controls write actions. Controls a role lacks simply don't render (or appear disabled).
  • Unchecking every box for a role reduces it to view-only + own password — that's honoured, not reverted to defaults.
  • Changes apply on save (no restart needed) and are stored under [roles] in nmc.conf.
  • RADIUS-authenticated users get the role picked in "Assigned Role" — that role's matrix row decides their access.

The four roles

RoleIntended use
AdministratorFull control — fixed, cannot be edited
Device OnlyOperators who manage the UPS but not network settings
Network-OnlyManages network/services/notifications, no UPS commands
Read-OnlyMonitoring only — no actions by default

Even with an edited matrix the server enforces the same capabilities — a hand-typed POST to a page the role can't use returns 403 and is logged.
