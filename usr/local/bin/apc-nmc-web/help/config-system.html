Configuration › System groups the network-level management cards. Roles without the matching capability see the controls greyed out. User accounts, RADIUS and sessions have moved to Users › User Access.

Network Services

  • Modbus TCP: serves UPS registers to BMS/SCADA clients — bind address, port (default 502), Unit ID, optional write access for UPS commands. Register map: docs/modbus-registers.md.
  • FTP Server: chrooted vsftpd for file transfer — enable only when needed and open the port in the firewall.
  • MQTT Telemetry: publishes UPS state JSON to <prefix>/state every Interval seconds — host, port, TLS, credentials. Save & Test sends a trial publish; the last publish result shows under the form.

Firewall

Manages nftables input rules: extra TCP/UDP ports to allow and optional source-CIDR restrictions. SSH/HTTP/HTTPS/NUT stay open. Be careful not to close the port you're connected through.

Wired Port Authentication (802.1X)

Ethernet port authentication for NAC-protected switches — not WiFi. Pick the wired interface, EAP method (PEAP/TTLS use a password; TLS uses client certs), identity and credentials. Leave disabled on a normal LAN.

WiFi Setup

  • Join a network: SSID + passphrase; Scan lists detected networks (requires the Network capability).
  • Wireless Hardware: fully enable/disable onboard WiFi and Bluetooth at boot level (dtoverlay). Changes need a reboot; the card shows "pending reboot" until then. Requires the System capability.

Disabling the radio you're connected through cuts access — confirm you have an alternative path (Ethernet) first.

Data Logging

Tunes the power-metrics history behind the Data Log chart and energy stats: Retention (hours kept, 24–720) and Write Batch (samples buffered before each SD write — higher is gentler on the card). Samples land once per minute.

Time & Date

Card clock settings — timezone (IANA name, searchable) and NTP sync via timedatectl. Affects log timestamps, weekly schedules and certificate validity. Requires the System capability.

Secure Boot

Shows secure-boot / boot-integrity status (background in docs/secure-boot.md).

Accounts

User accounts, the permission matrix, RADIUS and active sessions live on Users › User Access — see Roles for the capability model.
