No UPS data / "last valid reading" shown

  • Check the NUT services: systemctl status nut-server and the UPS driver service.
  • Check the cable/Modbus link to the UPS; upsc myups on the console should list variables.
  • If the UPS is new, make sure [ups] name in nmc.conf matches the entry in ups.conf.

Repeated spontaneous reboots

The network watchdog (net-watchdog) reboots the device when both gateway and internet probes stay dead — up to 3 times per continuous outage. Check the Event Log and the physical network first.

Can't reach the UI

  • If you disabled the WiFi radio you were using, connect over Ethernet and re-enable it under System › WiFi Setup › Wireless Hardware, then reboot.
  • Check ports 443/80 are allowed in the firewall settings.
  • systemctl status apc-nmc-web and its journal show web errors.

Update failed

  • The live console on About › System shows the failing step — usually network/GitHub reachability or checksum mismatch.
  • Use Rollback to return to the previous release; backups live in /var/backups/apc-nmc/.

Notifications not arriving

  • Use each channel's Test button — the exact failure lands in the Event Log.
  • SMTP: check port/security mode and credentials. Webhook: check the URL and the remote response.
  • Lower the Minimum Severity — the event may have been filtered out.

Modbus / MQTT not working

  • Modbus: enable the service and open its port in the firewall; check the client's Unit ID matches.
  • MQTT: use Save & Test; connect/TLS/auth errors show in the card and the Event Log.

Deeper debugging

On About › System, Download Support Bundle produces a tar.gz with sanitized config, service states and recent journals — ideal for a bug report.
