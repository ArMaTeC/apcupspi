Connecting Servers via NUT (upsd)

This card runs a full NUT server — any host that understands NUT can monitor and safely shut down from the UPS, the same role a vendor tool such as PowerChute Network Shutdown would fill. There is no APC-proprietary protocol: every client speaks the open NUT protocol to upsd on TCP 3493.

How it works

CardRuns upsd (NUT server) on :3493; the UPS driver (apc_modbus) feeds it telemetry and executes commands.
ClientsRun upsmon (NUT monitor) configured as a slave of this card — it watches status and shuts down cleanly on low battery.

Client setup (Linux, NUT)

Install nut-client on the server and edit /etc/nut/upsmon.conf:

MONITOR myups@<card-ip> 1 upsmon <password> slave
SHUTDOWNCMD "/sbin/shutdown -h +0"

Credentials come from the card's /etc/nut/upsd.users (generated at install — see README). The slave flag means this host waits for the card's shutdown signal rather than deciding alone.

Flood protection

upsd has no per-client rate limits. If many hosts poll status.json instead of upsmon, keep intervals ≥ 15 s. The dedicated NUT protocol is lightweight and scales to dozens of upsmon slaves.

PowerChute / Windows

PowerChute Network Shutdown expects APC's proprietary protocol and cannot pair with this card. Windows hosts can use NUT for Windows (WinNUT) or apcupsd in NIS mode pointed at myups@<card-ip> — both speak NUT.

Verifying

  • upsc myups@<card-ip> from a client lists live UPS variables.
  • Client-side upsc myups@<card-ip> ups.status should show OL (online) — OB on battery.
  • On low battery the card's event log records the transfer and every slave receives FSD (forced shutdown) when the card raises it.
